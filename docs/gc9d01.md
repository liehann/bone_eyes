# GC9D01 / Waveshare 0.71" notes

- **Library choice:** stock TFT_eSPI (2.5.43, master as of 2026-04) has no
  GC9D01 driver. PR #3783 adding one is still open.
  - Waveshare's demo bundles a patched TFT_eSPI 2.5.0 that replaces the
    GC9A01 branches.
  - Arduino_GFX ≥ 1.6.1 has `Arduino_GC9D01`.
  - We use neither. `src/gc9d01.{h,cpp}` drives ESP-IDF `spi_master`
    directly: manual CS per panel, manual DC, DMA from two 8-row internal-RAM
    buffers. That's about 200 lines, and it gives full control over
    two-panel CS handling with no library patching.
  - Each panel has its own lead. The right eye's CLK/DIN are copies of the
    VSPI signals routed through the GPIO matrix (`Gc9d01Bus::mirror`), and
    its DC/RST/BL follow the left eye's.
- **Init sequence:** verbatim from Waveshare `GC9D01_Init.h`, byte-identical
  to Arduino_GFX (re-checked 2026-10-22). Both references then send INVOFF
  (0x20); we do too. It's the reset default, so this is only for parity.
  - SPI mode 0, MSB first (Waveshare wiki, both libraries).
  - Reset 5/20/150 ms high/low/high matches TFT_eSPI. Arduino_GFX uses
    200/200/200.
  - DC is low for the command byte and high for its parameters and pixel data.
- **Geometry:** GRAM is 160×160 with no column/row offsets.
- **MADCTL:** MY 0x80, MX 0x40, MV 0x20, ML 0x10. RGB is 0x08 and BGR is 0x00,
  the reverse of the usual convention.
  - The panel runs dual-gate (`0xBF=0x01`). With MV set (90°/270°), even and
    odd lines swap unless ML is set (Arduino_GFX commit 42e6ce8a). The same
    commit flipped MY against the usual MX|MV / MY|MV, so ML evidently also
    reverses the line order here.
  - Per-eye rotation is `EYE_L_ROT` / `EYE_R_ROT` in `config.h`: degrees
    clockwise as seen from the front, relative to the native orientation
    (tip/FPC at the bottom). The values match Arduino_GFX `setRotation`:

    | rot | MADCTL | bits |
    |---|---|---|
    | 0 | 0x00 | – |
    | 90 | 0xF0 | MX MY MV ML |
    | 180 | 0xC0 | MX MY |
    | 270 | 0x30 | MV ML |

    `TFT_SWAP_RB` ORs in 0x08. The panel is 160×160 with no offsets, so the
    address window is the same in every rotation.
  - In the printed skull each module is turned 90° with its tip toward the
    nose (`hardware/eye_mount.scad`, `module_rot`). Seen from the front, the
    left eye (viewer's right, +X) is turned 90° clockwise and the right eye
    90° anticlockwise, so the defaults are L = 270 and R = 90. Use 0/0 on the
    old stand-alone bar (tip down).
  - The 90/270 values are from Arduino_GFX and not yet checked on our panels. `lcd madctl
    <L|R> <hex>` writes a raw byte for experiments.
- **SPI clock:** the datasheet write cycle is 10 ns min. Waveshare's demo uses
  27 MHz and DualEye_display uses 40 MHz. We default to 40 MHz, and both eyes
  run cleanly at 40 MHz on the bench, the right one through the GPIO matrix
  too. At 40 MHz one 160×160 frame takes 10.24 ms on the wire, so the shared
  bus caps two eyes at about 48 fps.
- **Bench diagnostics:** `lcd pins` (also prints each eye's rotation),
  `lcd rot [<L|R|both> <0|90|180|270>]` (show or set the rotation, then the
  test pattern), `lcd madctl <L|R> <hex>`, `lcd spi <MHz>` (re-adds the SPI device,
  re-inits, test pattern), `lcd init` (reset + init, white then red),
  `lcd fill r g b`, `lcd toggle <gpio>` (1 Hz for 10 s, LCD pins only). Each
  one pauses the eye animation like `eyes test`; `eyes anim` resumes it.
  `lcd prof` doesn't pause anything: it prints the average frame time since
  the last call, split into simulation, row rendering per core and SPI waits.
- **Module VCC is the header logic level, so wire it to 3V3.** Per the V2
  schematic, the 8-pin header (VCC, GND, DIN, CLK, CS, DC, RST, BL) goes to
  the B side of a TXB0108PWR whose VCCB is the module's VCC. The A side runs
  at the panel's 3.3 V from the on-board RT9193 LDO.
  - On 5 V, VCCB = 5 V and the TXB0108's V_IH is 0.65 × VCCB = 3.25 V, so
    the ESP32's 3.3 V outputs sit at the threshold. Bench result: a module on
    5 V stayed black with the backlight on; the same module on 3V3 works.
  - An earlier 40 MHz failure (1 MHz looked fine) was this 5 V VCC problem,
    not the clock: with VCC on 3V3, 40 MHz works on both eyes. The TXB0108
    is auto-direction with weak drive (about 4 kΩ output impedance plus edge
    one-shots), so keep the leads short, but it doesn't limit the clock here.
  - RST has an on-board RC power-on reset.
  - BL is active high through an NPN, defaults on when floating, and PWMs fine.
